TWO BUGS FROM THE SCREENSHOT, BOTH FIXED
--------------------------------------------------------------------------

THE WASHED-OUT NAV.  app/ground.css and components/Header.tsx were both
styling the same element and fighting.

  ground.css      body > header { background: navy; border: 4px gold }
  Header.tsx      className="... bg-transparent" for the top state

A Tailwind utility beats `body > header` on specificity, so the navy fill lost
and the gold border stayed. The cream type then painted onto the white page
behind it. That is the pale bar in the gold box.

The deeper mistake was mine: I built the top state assuming it sat on the navy
hero. It does not. ground.css frames the page in white gutters, so the bar
floats above the hero on white.

Fixed both ways round. ground.css now owns GEOMETRY ONLY -- width and sticky
offset -- and the component owns appearance, because the component is the only
thing that knows which scroll state it is in. And the bar is LIGHT in both
states: solid white with a gold hairline at the top, translucent white with a
blur and less padding once scrolling. What changes is weight, not colour, so
it never has to guess what is behind it.

THE HERO TYPE.  The accent phrase was set in JetBrains Mono. That was chosen
when the brief for this site said "high-tech" and a monospaced phrase inside a
display line read as deliberate. On the light redesign it reads as a rendering
fault -- two words of wide monospace mid-headline look like a font failed to
load. It is gold in the display face now.

The headline was also clamp(3.4rem, 5.2vw, 5rem) at a 0.94 line height, sized
for a dark page where it was the only thing on screen. Six words over four
lines, each nearly as tall as the portrait. Now clamp(2.6rem, 3.5vw, 3.7rem),
line height 1.04, tracking -0.032em, capped at 15ch so it breaks sensibly.
Crisp is tracking and line height far more than size.

LARK, AS A PERSISTENT WIDGET
--------------------------------------------------------------------------

components/LarkLauncher.tsx is new. It WRAPS the existing Assistant rather
than replacing it, so the two-turn capture bound, the server-rendered offline
state, the refusal handling and the source tagging all carry over untouched.
Only the shell is new.

  Collapsed   small bottom-right pill: the meadowlark mark, "Lark", a green
              online dot with a screen-reader label, and "Have a real estate
              question?"
  Expanded    a 26rem card on desktop, full width on a phone. Not a takeover.
  Escape      closes it AND returns focus to the launcher, so a keyboard
              visitor does not land back at the top of the document.

NO BIRD LORE. The mark stays as a silent avatar, as agreed. What is gone is
the paragraph explaining what a lark is. An avatar is a face, not a story.

PAGE-AWARE CHIPS, from section 11.3, living in the component rather than in
content/site.json: a chip is a property of the interface, not of the page's
copy. It changes when the route's JOB changes, not when its wording does.

Exactly three per route, because lib/schema.ts declares
AssistantChip.array().length(3). The brief lists four for home; "Help me
analyze a rental" is dropped, since the investors page carries it and a
duplicate earns the least.

MOBILE. The pill sits bottom-right and the panel is full width there. The brief
forbids covering a submit button or a consent control, and a floating card over
the middle of a 390px screen does exactly that. Panel height uses dvh, not vh,
so iOS Safari's collapsing toolbar cannot push the input off screen.

MOUNTED AFTER THE FOOTER in app/layout.tsx, so it is last in the DOM and last
in the tab order. A launcher that grabs focus before the navigation would be
worse than not having one.

`initialConfigured` is read on the SERVER, so the first paint already knows
whether an API key exists. Without it a visitor with slow JS sees an online dot
on an assistant that cannot answer.

The assistant BAND is retired in Bands.tsx and returns null. Zero content files
still carried one -- batch 1's page cuts had already removed them all.
